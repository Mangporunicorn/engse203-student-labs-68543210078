## 4. เหตุผลของการเลือกชนิดและข้อกำหนด

### ทำไม `users.id` กับ `requests.id` ใช้ชนิดต่างกัน

`users.id` ใช้ `INTEGER` และ `AUTOINCREMENT` เพราะเป็นรหัสภายในฐานข้อมูล เราไม่ได้จำเป็นต้องให้ผู้ใช้อ่านหรือจำรหัสนี้ จึงให้ SQLite สร้างหมายเลขต่อไปให้อัตโนมัติ เช่น `1`, `2`, `3`, `4`

ส่วน `requests.id` ใช้ `TEXT` เพราะรูปแบบรหัสคำร้องของระบบเป็น `REQ-001`, `REQ-002` เป็นต้น รหัสแบบนี้ช่วยให้ดูแล้วรู้ทันทีว่าเป็นรหัสคำร้อง และสามารถนำไปแสดงให้ผู้ใช้เห็นได้ง่ายกว่าตัวเลขอย่างเดียว

### ทำไมต้องมี CHECK constraint ทั้งที่ API ก็ตรวจข้อมูลอยู่แล้ว

ถึงแม้ API จะตรวจข้อมูลก่อนบันทึก แต่ฐานข้อมูลก็ควรตรวจข้อมูลอีกชั้นหนึ่ง เพราะข้อมูลอาจไม่ได้เข้ามาทาง API อย่างเดียว เช่น อาจมีการใช้ SQL เพิ่มหรือแก้ข้อมูลโดยตรง

ถ้ามีแค่การตรวจที่ API อย่างเดียว แล้วมีข้อมูลถูกเพิ่มจากช่องทางอื่น ก็อาจมีค่าที่ระบบไม่รองรับหลุดเข้าไปในฐานข้อมูลได้

ตัวอย่างเช่น `status` ของระบบกำหนดไว้เพียง

```text
pending
in-progress
completed
```

ถ้ามีคนพยายามบันทึกค่าอย่าง `cancelled` หรือค่าอื่นที่ไม่ได้กำหนดไว้ `CHECK` constraint จะไม่ยอมให้ข้อมูลนั้นถูกบันทึกลงฐานข้อมูล

ดังนั้นการตรวจที่ API ช่วยตรวจข้อมูลก่อนส่งเข้าฐานข้อมูล ส่วน `CHECK` constraint เป็นการป้องกันข้อมูลผิดที่ระดับฐานข้อมูลอีกชั้นหนึ่ง

## 5. ตัวอย่างการใช้ JOIN
